# CloudBase 双实例接入方案（已确认并实施）

## 已复核的现状

2026-09-17 通过 CloudBase 管理工具确认：环境 `mmemo-d5g6fybcm3b31a52d` 正常，地域上海；PostgreSQL 已配置，NoSQL/MySQL 未配置；用户名密码登录已开启；public schema 当前无业务对象。桌面仍通过 Swift TaskStore 读写本地 JSON，勾选和 AI 批量变更都写本地，未接入应用用户认证或云同步。

## 推荐的本轮范围

- 两个固定开发账号 A/B，属于同一个开发共享空间。管理端创建账号；普通客户端只使用自己的应用用户身份，不携带管理密钥。
- Swift 原生层通过官方 Auth / PG HTTP API 登录、刷新会话、读取与提交数据。当前项目是 Swift + 本地 WebKit，并非 JS SDK Web 应用；继续保持网页不联网的边界。
- 两个独立 App 实例、bundle ID、数据目录、登录会话、窗口偏好和已读提醒记录；入口默认分开停靠，菜单显示 A/B，避免重叠误认。启动脚本提供一次构建、双实例启动路径。
- 云端持久化待办和共享成员关系，PG 行级权限只允许该空间成员访问。字段至少包括 id、space_id、title、due、done、created_by、updated_at；身份存稳定用户 ID，在各客户端转换为我/对方，禁止在云端存相对视角的 me/partner。
- 云端为共享数据事实源；本地 JSON 保留为独立缓存和原子备份。开发空间初始为空，不自动上传、覆盖当前个人实例已有待办。
- 首版每 3 秒同步一次，打开面板及写入完成时立即刷新；失败退避、界面明确失败，不把未确认写入显示成成功。不做离线写入队列或 CRDT。
- 不同待办独立更新，同一字段按服务器提交顺序最后写入生效。AI 批量操作经一个服务端事务提交，只写实际变更字段，避免旧列表覆盖其他客户端的新内容；删除目标已不存在等情况明确处理。
- 同步刷新不清空输入草稿、引用和消息详情；令牌失效后刷新会话，失败则提示重新登录。

## 取舍

1. 推荐：Swift + 官方 HTTP API + 短轮询。保留现有桌面架构，最小依赖，先验证真实双人共享；这是轮询同步，不宣称 WebSocket 实时推送。
2. 将官方 JS SDK 装入 WebKit：SDK 管理登录更便利，但需要增加构建、网络 CSP 与原生通信改造。
3. 自建常驻同步服务：可扩展，但当前两个固定用户不需要额外服务运维。

## 验收

- 两个独立登录身份能读取同一共享空间；A 新增、B 完成、A 更新、B 删除都经云端双向反映。
- 两端同时修改不同待办不丢失更新；失败批次不出现部分提交。
- 匿名及非成员无法读写；用户不能伪造创建者或自行加入其他空间。
- 网络失败不报成功，恢复后能重新同步；重启后保留各自身份、位置和云端数据。
- 本地原有待办不变；验收数据限开发空间，验收后清理。
- 真实 AI 请求仅做一条最小联调；主要同步/权限测试直接操作应用存储边界，不进行批量模型调用。

## 本轮不包含

开放注册、邀请流程、复杂多空间管理、Web Push、移动端、待对方确认的完整审批流程。上述功能另行设计。
